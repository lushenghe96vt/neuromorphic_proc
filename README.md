# Subthreshold Neuromorphic SoC

An ultra-low-power, event-driven neuromorphic processor designed for a Tiny Tapeout silicon shuttle.

This repository is the shared starting point for the student teams developing the RTL, verification environment, custom cells, and physical implementation of a class-wide neuromorphic system-on-chip.

## Project at a Glance

| Item | Target |
| --- | --- |
| Sponsor | Future Artificial Intelligence Limited (FAIL) |
| Shuttle | Tiny Tapeout silicon shuttle |
| Target technology | SkyWater 130 nm (`sky130A`) or GlobalFoundries 180 nm (`GF180MCU`) |
| Nominal supply | `0.45 V` subthreshold / weak inversion |
| Master clock | `2 MHz` |
| Slow timer clock | `100 kHz` |
| Scan clock | `100 kHz` |
| RTL | SystemVerilog |
| Implementation | Synthesis, place and route, subthreshold STA, custom low-voltage cells |

> This README defines the initial architectural contract. Teams should propose changes through an interface review before changing shared ports, packet formats, clocking, reset behavior, or scan-chain order.

### Clocking and storage decisions

The baseline chip does **not** require a PLL or an SRAM/memory macro.

- **Clock source:** `CLK_EXT` supplies the nominal `2 MHz` system clock. The `100 kHz` slow clock may be generated by dividing `CLK_EXT` by 20. The architecture review must decide whether the `100 kHz` scan clock uses that divided clock or a separate external clock. `SPI_SCLK` remains an independent external clock and requires explicit clock-domain handling.
- **State storage:** neuron state, weights, configuration registers, counters, and small lookup tables should use flip-flops, register arrays, or synthesized ROM logic. The current requirements do not justify the area, ports, or characterization risk of a compiled SRAM.
- **Configuration:** Team 5 receives configuration over SPI and distributes it to the relevant blocks; configuration storage is register-based in the baseline design.
- **Future expansion:** an SRAM or PLL may be proposed only if a team demonstrates a concrete capacity, frequency, or clock-quality requirement and provides the additional interface, verification, low-voltage characterization, and physical-design work.

## What Each Team Builds

The class SoC is divided into five blocks. Each team owns one block, its RTL, its unit testbench, and the evidence that the block meets its interface contract.

| Team | Block | Main responsibility |
| --- | --- | --- |
| Team 1 | Digital AER wrapper and configuration engine | Connect the teaching-assistant analog core to the digital AER network and configure synaptic DACs |
| Team 2 | Synthesized subthreshold digital SNN tile | Process events for 32 logical neurons with a time-multiplexed fixed-point LIF pipeline |
| Team 3 | On-chip plasticity engine | Track spike timing, evaluate STDP updates, and maintain bounded weights |
| Team 4 | Asynchronous AER router | Route 10-bit events through a clockless five-port network |
| Team 5 | SoC infrastructure and top integration | Provide SPI, calibration, clock/reset distribution, scan integration, and top-level assembly |

### Team rules

- Teams normally contain two students. Three-person teams require instructor approval and a written division of work.
- Every team must maintain a block-level microarchitecture document, RTL, unit testbench, and integration notes.
- Graduate students must either implement at least two Tiny Tapeout blocks or operate below `0.8 V`, targeting the nominal `0.45 V` regime.
- Teams may instead propose an independent IP core that uses the Tiny Tapeout I/O budget and includes an FSM or controller with at least 32 states.

### Workload parity between project paths

The independent-IP path and the neuromorphic-SoC path are graded as equivalent engineering projects. The 32-state FSM requirement applies only to an independent IP core; it is not a shortcut for measuring the workload of a neuromorphic block.

Every neuromorphic team must own all of the following work for its assigned block:

- **Architecture:** a microarchitecture document with datapath or protocol diagrams, a state or transaction model, timing assumptions, resource estimates, and defined corner cases;
- **Implementation:** a substantive SystemVerilog design with at least two interacting functional responsibilities, such as a datapath plus controller, protocol engine plus buffering, or calibration plus scan control. A wrapper that only renames or wires signals is not sufficient;
- **Verification:** a self-checking unit testbench, directed corner-case tests, randomized or stress traffic where applicable, assertions for the block protocol, and an integration-level test;
- **Physical implementation:** synthesis results, area and timing reports, and a place-and-route or macro-layout result with documented subthreshold constraints;
- **Custom-cell contribution:** schematic, layout, characterization, or gate-level integration work for the shared low-voltage inverter and scan-DFF library;
- **Integration ownership:** a tested top-level connection, scan-chain participation, interface review, and a reproducible handoff package.

An independent-IP team must submit the same six categories, plus the required controller or FSM with at least 32 meaningful architectural states. A neuromorphic team cannot receive equivalent-path credit by delivering RTL alone, and an independent-IP team cannot receive it by delivering an FSM without physical-design and verification evidence.

## System Architecture

```text
                         TOP-LEVEL SOC (0.45 V)
  +-----------------------------------------------------------------------+
  | Team 5: SoC management, calibration, power distribution, scan master  |
  +-----------------------------------------------------------------------+
       |                 |                 |                 |
       v                 v                 v                 v
  +---------+ AER   +---------+ AER   +---------+ AER   +---------+
  | TA      |<----->| Team 2  |<----->| Team 3  |<----->| Team 4  |
  | analog  |       | SNN     |       | STDP    |       | async   |
  | macro   |       | tile    |       | engine  |       | router  |
  +---------+       +---------+       +---------+       +---------+
       ^                 ^                 ^                 ^
       +=================+=================+=================+
                    global scan chain
```

The scan chain runs through Teams 1-4 and returns to Team 5. The AER path carries event requests, acknowledgements, and addresses between neighboring blocks.

## RTL Block Contracts

The following declarations are the starting interfaces. Teams may add internal signals and parameters, but shared ports should remain stable until the architecture review.

### Team 1: AER wrapper and configuration

#### What this block does

This block is the digital adapter between the teaching-assistant analog macro and the AER network. The analog macro presents 16 one-bit neuron outputs. When one or more outputs assert, Team 1 selects a neuron, places its address on `AER_ADDR`, and raises `AER_REQ`. The address and request remain stable until Team 4 returns `AER_ACK`. After the acknowledgement, the wrapper completes the transaction and may send the next event.

The upper nibble of `AER_ADDR` is the fixed tile ID (`4'b0001`). The lower nibble is the selected neuron ID (`0` through `15`). If multiple `SPIKE_OUT` bits are high together, the team must choose and document a deterministic policy, such as fixed priority or round robin. The design must not silently lose events without documenting the behavior.

`CFG_WE` and `CFG_DATA` provide a simple configuration write. On an accepted write, store the 64-bit value in `WEIGHT_DAC` and hold it until the next accepted write or reset. Define the write acceptance condition in the microarchitecture document; the baseline assumption is that `CFG_WE` is synchronous to `CLK`.

#### What students implement

- one-event-at-a-time AER request controller;
- pending-spike tracking and a documented multi-spike priority policy;
- the 64-bit configuration register;
- the scan shift path from `SI` to `SO`;
- reset behavior that clears `AER_REQ`, `AER_ADDR`, and `WEIGHT_DAC` to documented values.

The testbench should check that the address and request stay stable while waiting for `AER_ACK`, that no event is accepted twice, and that every selected spike is either transmitted or explicitly accounted for.

```systemverilog
module block1_aer_wrapper (
    input  logic        CLK,
    input  logic        RST_N,
    input  logic        SE,
    input  logic        SI,
    input  logic [15:0] SPIKE_OUT,
    input  logic        AER_ACK,
    input  logic        CFG_WE,
    input  logic [63:0] CFG_DATA,
    output logic        SO,
    output logic        AER_REQ,
    output logic [7:0]  AER_ADDR,
    output logic [63:0] WEIGHT_DAC
);
endmodule
```

### Team 2: Digital SNN tile

#### What this block does

This block receives an AER event, identifies the source neuron from `AER_IN_ADDR`, updates one logical neuron, and optionally emits a new spike. It represents 32 logical neurons but uses one shared arithmetic datapath, so a neuron update is spread across several `CLK` cycles. The controller must remember which neuron is being processed and must not accept a new event until it can preserve the current event and state.

Use the following formats unless the architecture review approves alternatives:

- membrane voltage `V_M`: signed 12-bit Q4.8;
- leak or decay coefficient `beta`: unsigned Q0.8;
- synaptic weight `W`: signed 8-bit;
- arithmetic intermediates: wide enough to avoid accidental truncation before saturation.

The exact LIF update equation, threshold, reset voltage, and post-spike reset must be written in the team microarchitecture document. A useful baseline sequence is: capture event, read neuron state, add the signed weight, apply leak, compare against threshold, write the next state, and emit a spike if the threshold was crossed.

The upper nibble of `AER_OUT_ADDR` is the fixed tile ID (`4'b0010`). The lower nibble identifies the source neuron or event source according to the interface document.

#### What students implement

- a 32-entry neuron-state register array;
- a time-multiplexed fixed-point datapath;
- a controller that sequences capture, arithmetic, state write-back, and output event transmission;
- input and output AER handshakes with backpressure;
- signed arithmetic, saturation, threshold crossing, and post-spike reset;
- the scan shift path from `SI` to `SO`.

The testbench should exercise positive and negative weights, minimum and maximum values, threshold crossings, an event arriving while the output is blocked, and two events targeting different neurons.

```systemverilog
module block2_digital_snn (
    input  logic       CLK,
    input  logic       RST_N,
    input  logic       SE,
    input  logic       SI,
    input  logic       AER_IN_REQ,
    input  logic [7:0] AER_IN_ADDR,
    input  logic       AER_OUT_ACK,
    output logic       SO,
    output logic       AER_IN_ACK,
    output logic       AER_OUT_REQ,
    output logic [7:0] AER_OUT_ADDR
);
endmodule
```

### Team 3: STDP learning engine

#### What this block does

This block changes synaptic weights using spike timing. `PRE_SPIKE` and `POST_SPIKE` indicate pre- and post-synaptic activity. `CLK_SLOW` advances the timing information used to estimate the interval between spikes. The engine evaluates a positive or negative learning update and applies it to the stored signed weights.

The weight update is:

$$W_{new} = W_{old} + \Delta W$$

Weights must saturate to the signed 8-bit range `[-128, 127]`; they must not wrap around. The exponential-decay values may be implemented as a small ROM, case statement, or synthesized lookup table. The team must document the table entries, the interval quantization, and which spike combinations cause potentiation, depression, or no update.

The interface exposes 16 eight-bit weights through `WEIGHT_OUT[127:0]`. Document the mapping: weight channel `n` is `WEIGHT_OUT[8*n +: 8]`. The four-bit spike inputs therefore require a documented mapping or time-multiplexing scheme for the 16 channels.

`LEARNING_DONE` should pulse for one `CLK` cycle when a requested learning operation has completed. Define what constitutes a request in the microarchitecture document; if learning is continuous, document the event that causes the pulse.

#### What students implement

- timing counters driven by `CLK_SLOW`;
- spike-history storage for each plastic channel;
- interval quantization and decay lookup;
- signed delta calculation and saturating weight update;
- a `CLK`-domain completion signal with any required synchronization;
- the scan shift path from `SI` to `SO`.

The testbench should check no-spike, pre-before-post, post-before-pre, simultaneous spikes, interval limits, positive saturation, negative saturation, reset values, and the `CLK`/`CLK_SLOW` clock-domain boundary.

```systemverilog
module block3_stdp_learning (
    input  logic         CLK,
    input  logic         CLK_SLOW,
    input  logic         RST_N,
    input  logic         SE,
    input  logic         SI,
    input  logic [3:0]   PRE_SPIKE,
    input  logic [3:0]   POST_SPIKE,
    input  logic [3:0]   CAL_VEC,
    output logic         SO,
    output logic [127:0] WEIGHT_OUT,
    output logic         LEARNING_DONE
);
endmodule
```

### Team 4: Asynchronous AER router

#### What this block does

This block moves event packets without using a global clock. It has five ports: local, north, south, east, and west. Each port uses a four-phase request/acknowledge handshake:

1. The sender places valid data on the bus and raises `REQ`.
2. The receiver captures the data and raises `ACK`.
3. The sender lowers `REQ`.
4. The receiver lowers `ACK`, returning the link to idle.

The sender must keep its data stable from the rising edge of `REQ` until the receiver has acknowledged it. The router must not acknowledge a request until it has accepted the packet, and it must not release an input until the selected output transaction has completed.

A 10-bit event packet uses `[9:8]` for the header, `[7:4]` for the source tile, and `[3:0]` for the source ID. The team must define the destination or routing interpretation of the header and publish a route table for the class floorplan. When two inputs request the same output, an arbiter must select one request, prevent duplication, and provide a documented fairness policy.

#### What students implement

- one input transaction controller per port or an equivalent shared controller;
- route decoding from the packet header;
- arbitration for output contention;
- bundled-data stability and four-phase return-to-zero handshakes;
- deadlock and illegal-route behavior;
- the scan shift path from `SI` to `SO`.

This block is asynchronous. Do not add a clock just to simplify the RTL without approval. The testbench should check one-hop forwarding, simultaneous requests, contention, fairness, back-to-back packets, reset/idle behavior, malformed headers, and return-to-zero sequencing.

```systemverilog
module block4_async_router (
    input  logic        SE,
    input  logic        SI,
    input  logic        REQ_IN_LOCAL,
    input  logic [9:0]  DATA_IN_LOCAL,
    input  logic        ACK_OUT_LOCAL,
    output logic        ACK_IN_LOCAL,
    output logic        REQ_OUT_LOCAL,
    output logic [9:0]  DATA_OUT_LOCAL,
    input  logic [3:0]  REQ_IN_NSEW,
    input  logic [9:0]  DATA_IN_NSEW [3:0],
    input  logic [3:0]  ACK_OUT_NSEW,
    output logic [3:0]  ACK_IN_NSEW,
    output logic [3:0]  REQ_OUT_NSEW,
    output logic [9:0]  DATA_OUT_NSEW [3:0],
    output logic        SO
);
endmodule
```

### Team 5: SoC manager and top integration

#### What this block does

Team 5 is the integration owner. It connects the external pads to the four macro blocks, distributes clocks and reset, controls the global scan enable, accepts configuration over SPI, and assembles the top-level floorplan.

The SPI interface has `SPI_SCLK`, active-low `SPI_CS_N`, `SPI_MOSI`, and `SPI_MISO`. The team must define the SPI mode, command format, register addresses, bit order, and behavior when chip select is released. Configuration values must be transferred safely from the SPI clock domain into the `CLK_EXT` domain.

`CLK_EXT` is the external `2 MHz` clock. `CLK_INT` is its integrated or buffered copy. `CLK_SLOW_INT` is the approved `100 kHz` slow clock. `RST_N_INT` must remain asserted until the internal clock/reset distribution is valid. `GLOBAL_SE` controls scan mode, and the scan chain must connect `SCAN_IN` through Teams 1-4 to `SO_FROM_TEAM4` and then to `SCAN_OUT`.

`RO_SENSE_IN` represents the ring-oscillator measurement input. Team 5 counts or samples it using a defined observation window and produces the four-bit calibration vectors. The calibration algorithm, update timing, and safe behavior when the sensor is missing must be documented.

#### What students implement

- SPI receiver/transmitter and a documented register map;
- clock-domain crossing from `SPI_SCLK` to `CLK_EXT`;
- clock divider or approved source for `CLK_SLOW_INT`;
- reset synchronizer and internal reset distribution;
- global scan enable and scan-chain assembly;
- ring-oscillator measurement and calibration-vector generation;
- top-level instantiation, pin connection, power-domain labels, and integration constraints.

The testbench should check SPI reads and writes, chip-select interruption, reset release, clock division, scan-chain continuity, calibration minimum and maximum values, and safe behavior for invalid commands.

```systemverilog
module block5_soc_top_manager (
    input  logic       CLK_EXT,
    input  logic       RST_N_EXT,
    input  logic       SPI_SCLK,
    input  logic       SPI_CS_N,
    input  logic       SPI_MOSI,
    input  logic       SCAN_IN,
    input  logic       SO_FROM_TEAM4,
    input  logic       RO_SENSE_IN,
    output logic       SPI_MISO,
    output logic       SCAN_OUT,
    output logic       CLK_INT,
    output logic       CLK_SLOW_INT,
    output logic       RST_N_INT,
    output logic       GLOBAL_SE,
    output logic       SI_TO_TEAM1,
    output logic [3:0] CAL_VEC_1,
    output logic [3:0] CAL_VEC_3
);
endmodule
```

## Common RTL Expectations

Before writing the full implementation, every team should answer these questions in its microarchitecture document:

1. What is the reset state of every output and handshake signal?
2. What does a request mean, and when may the sender change the associated data?
3. What event causes an acknowledgement, and how is backpressure handled?
4. What happens when two events arrive in the same cycle?
5. What is the behavior during scan enable (`SE`)?
6. Which signals cross clock domains, and how are they synchronized?
7. What are the latency, throughput, storage, and overflow assumptions?

Use synchronous active-low reset for clocked logic unless the integration review approves another choice. Do not infer latches. Keep combinational outputs fully assigned, and document any intentional clock-domain or asynchronous handshake boundary.

## Verification Definition of Done

A block is ready for integration when:

- reset, idle, normal operation, backpressure, and illegal-input behavior are covered;
- the testbench checks the interface contract rather than only internal signals;
- assertions cover request/acknowledge sequencing and stable data while a request is active;
- fixed-point arithmetic, signedness, saturation, and boundary values have directed tests;
- randomized or constrained-random traffic has been run where the block accepts events;
- simulation passes with no unexplained warnings or `X` propagation;
- synthesis completes without unintended latches, inferred tri-states, or undriven ports;
- a short results summary is checked into `reports/`.

For Team 4, include tests for simultaneous requests, contention, fairness, four-phase return-to-zero behavior, and the absence of a global clock. For Team 5, include scan-chain continuity, SPI transactions, reset distribution, and calibration boundary tests.

## Foundational Cell Work

Before macro implementation, all teams contribute to the low-voltage library effort:

1. Build and characterize a `1.5x` finger-scaled inverter at `0.45 V`.
2. Design a custom subthreshold scan D flip-flop.
3. Run schematic simulation and Monte Carlo timing sweeps.
4. Complete layout, DRC, LVS, parasitic extraction, and characterization.
5. Produce a usable Liberty model and clean scan-DFF layout for synthesis and gate-level simulation.

Record supply voltage, process corner, temperature, load, slew, delay, setup, hold, and failure criteria for every characterization result.

## First Commit for a New Team

1. Copy your assigned module declaration into `rtl/`.
2. Add a compilable empty module and a smoke-test testbench.
3. Add `docs/microarchitecture.md` with state diagrams, timing tables, and assumptions.
4. Add at least one reset test and one normal-operation test.
5. Open an interface issue for every unresolved port, packet, clock, or reset question.

Do not wait for the complete algorithm before making the first commit. A compiling shell and executable testbench give the integration effort something concrete to review.
